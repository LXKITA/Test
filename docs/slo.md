# SLO учебного API

## Область

Окно — скользящие 30 дней. Запросы `/metrics` исключаются как служебные.
Плановые работы не исключаются: пользователь всё равно видит недоступность.

## Availability

- SLI: доля HTTP-запросов, завершившихся не 5xx.
- SLO: не менее 99,9% за 30 дней.
- PromQL: recording rule `devops_api:availability_30d` из
  `monitoring/prometheus-rules.yaml`.
- Error budget: 0,1% запросов. При непрерывной полной недоступности это
  примерно 43 минуты 50 секунд за 30 дней.

## Latency

- SLI: доля успешных запросов с длительностью не более 500 ms.
- SLO: не менее 95% за 30 дней.
- Источник: `http_request_duration_seconds_bucket`.

## Политика error budget

- Израсходовано менее 50%: обычный выпуск изменений.
- 50–100%: только низкорисковые изменения, обязательный canary/rollback plan.
- Budget исчерпан: feature-релизы приостановлены; приоритет — reliability.

SLA в учебном проекте отсутствует: это договорное обязательство, а не
внутренняя инженерная цель.
